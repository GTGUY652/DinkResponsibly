# 0001 Admin Dashboard Specification

**Status**: Proposed

## Summary

The Admin Dashboard provides court owners and venue staff with a centralized, role based management interface. It enables real-time verification of paid guest bookings, management of customer support tickets, instant control over court operational rates, staff account management, and Gemini AI powered sales analytics.

## Context

The booking engine operates on a direct guest checkout model where customers make court reservations without creating accounts. The venue front desk and owners require a secure, desktop and mobile responsive administration portal to verify incoming guests via unique booking reference codes, update court pricing dynamically, reply to customer inquiries, and evaluate revenue trends.

## Requirements

### Acceptance Criteria

- **AC-1**: Authenticated access restricted to authorized accounts via Supabase Auth with custom user metadata roles (`OWNER` vs `STAFF`).
- **AC-2**: Default landing view displays a real-time table of all paid court reservations showing guest name, email, phone number, booking reference code, court name, date, reserved hours, total price, payment channel, and direct link to the official PayMongo Digital Receipt.
- **AC-3**: Instant venue check-in search bar and filter allowing staff to locate bookings by reference code (for example `PB-8942A`), guest name, or date.
- **AC-4**: Real-time status indicators showing live payment status (`CONFIRMED` in green).
- **AC-5**: Owner exclusive Court Rate and Operational Status Controller allowing live updates to weekday daytime rates (₱400 per hour), weekday nighttime rates (₱500 per hour), weekend flat rates (₱500 per hour), and active court toggles.
- **AC-6**: Real-time broadcast of rate changes and court status updates to all connected client applications using Supabase Realtime subscriptions.
- **AC-7**: Support ticket management portal displaying incoming inquiries with unique ticket references (for example `TICK-1042`), guest details, subject, message, and current status (`OPEN` or `RESOLVED`).
- **AC-8**: Direct email reply feature from the support ticket interface using the Resend Edge Function (`send-email`), dispatching responses straight to the guest's inbox.
- **AC-9**: Owner exclusive Staff Management portal to create, list, and deactivate staff user accounts.
- **AC-10**: Owner exclusive Sales Analytics dashboard displaying visual key performance metrics, revenue breakdowns by court, and popular booking time slots.
- **AC-11**: Interactive Gemini AI Business Advisor widget allowing the Owner to ask natural language questions (for example "Summarize sales for this week") and receive structured business reports generated by the `gemini-advisor` Edge Function.
- **AC-12**: Full mobile, tablet, and desktop layout responsiveness with accessible UI components.

## Proposed Architecture & Design

### Data Model

The PostgreSQL database schema hosted on Supabase consists of five core tables:

```sql
-- 1. Admin Profiles (linked to auth.users)
CREATE TABLE public.profiles (
  id UUID PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE,
  email TEXT NOT NULL UNIQUE,
  full_name TEXT NOT NULL,
  role TEXT NOT NULL CHECK (role IN ('OWNER', 'STAFF')),
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 2. Courts
CREATE TABLE public.courts (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL UNIQUE,
  description TEXT,
  hourly_rate NUMERIC(10, 2) NOT NULL DEFAULT 400.00,
  is_active BOOLEAN NOT NULL DEFAULT TRUE,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 3. Dynamic Pricing Rules (Future-proof extension)
CREATE TABLE public.court_pricing_rules (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  court_id UUID REFERENCES public.courts(id) ON DELETE CASCADE,
  day_type TEXT NOT NULL CHECK (day_type IN ('WEEKDAY', 'WEEKEND', 'HOLIDAY')),
  start_hour INT NOT NULL CHECK (start_hour BETWEEN 0 AND 23),
  end_hour INT NOT NULL CHECK (end_hour BETWEEN 0 AND 23),
  hourly_rate NUMERIC(10, 2) NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 4. Bookings
CREATE TABLE public.bookings (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  booking_reference TEXT NOT NULL UNIQUE,
  guest_name TEXT NOT NULL,
  guest_email TEXT NOT NULL,
  guest_phone TEXT NOT NULL,
  court_id UUID NOT NULL REFERENCES public.courts(id),
  start_time TIMESTAMPTZ NOT NULL,
  end_time TIMESTAMPTZ NOT NULL,
  total_price NUMERIC(10, 2) NOT NULL,
  status TEXT NOT NULL DEFAULT 'CONFIRMED' CHECK (status IN ('CONFIRMED', 'CANCELLED')),
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 5. Payments
CREATE TABLE public.payments (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  booking_id UUID NOT NULL REFERENCES public.bookings(id) ON DELETE CASCADE,
  payment_provider TEXT NOT NULL DEFAULT 'paymongo',
  payment_intent_id TEXT NOT NULL UNIQUE,
  receipt_url TEXT,
  amount NUMERIC(10, 2) NOT NULL,
  status TEXT NOT NULL CHECK (status IN ('PAID', 'REFUNDED')),
  payload JSONB,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 6. Support Tickets
CREATE TABLE public.support_tickets (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  ticket_reference TEXT NOT NULL UNIQUE,
  guest_name TEXT NOT NULL,
  guest_email TEXT NOT NULL,
  subject TEXT NOT NULL,
  message TEXT NOT NULL,
  status TEXT NOT NULL DEFAULT 'OPEN' CHECK (status IN ('OPEN', 'RESOLVED')),
  admin_reply TEXT,
  replied_by UUID REFERENCES auth.users(id),
  replied_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
```

### Role Based Access Control (RBAC Matrix)

| Feature / Action | Owner (Admin) | Staff |
|---|:---:|:---:|
| **Login & Dashboard Access** | Allowed | Allowed |
| **View Paid Transactions & Check-in Search** | Allowed | Allowed |
| **View & Reply to Support Tickets** | Allowed | Allowed |
| **View Sales Analytics Charts** | Allowed | Allowed |
| **Modify Court Hourly Rates & Toggles** | Allowed | Restricted |
| **Manage Staff Accounts** | Allowed | Restricted |
| **Query Gemini AI Business Advisor** | Allowed | Restricted |

## Consequences

- **Security**: Supabase Row Level Security policies enforce strict RBAC at the database level, preventing Staff accounts from executing rate changes or accessing AI business reports directly via API endpoints.
- **Maintainability**: Clean Architecture layer separation keeps presentation components decoupled from Supabase client code, making UI updates straightforward.
- **Scalability**: Added `court_pricing_rules` table allows future dynamic rate customization (for example holiday surges or seasonal pricing) without schema refactoring.
